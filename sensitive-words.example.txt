# 敏感词表 · 模板
#
# 这个文件是**模板**，说明该往仓库外的词表里填哪些类别。
# 真正在用的词表**不能进仓库**——它装的就是敏感值本身。
#
# 用法（二选一）：
#   DW_SENSITIVE_WORDS_FILE=/绝对路径/words.txt node scripts/sensitive-scan.mjs
#   DW_SENSITIVE_WORDS='词1,词2' node scripts/sensitive-scan.mjs
# CI 里放仓库 Secret（本仓库 CI 用的是 `DW_SENSITIVE_WORDS`）。
#
# 格式：一行一个；`#` 开头是注释；长度 <3 的词会被忽略（否则全仓库打成筛子）。
# 大小写不敏感，按**字面**匹配（正则元字符会被转义）。

# ── 1. 环境域名 ─────────────────────────────────────────────
# 生产/测试/预发的域名或子域。写域名主干就够，不必写全 URL。
<your-env-domain>
<your-test-domain>

# ── 2. 口令特征 ─────────────────────────────────────────────
# 口令的**固定片段或格式特征**（不是完整口令）。
# 例：公司统一口令前缀、口令里的年份段、生成规则的特征部分。
<password-fragment>
<password-pattern-hint>

# ── 3. 内部逻辑库名 / 服务名 ────────────────────────────────
# 中间件、网关、微服务的内部命名（不进公网的标识）。
<internal-service-prefix>
<internal-schema-prefix>

# ── 4. 业务表名 / 物化视图名 ────────────────────────────────
# 数仓里真实存在的表名、MV 名。哪怕只泄漏一个名字，也等于暴露了业务模型。
<real-table-name>
<real-mv-name>

# ── 5. 其它 ────────────────────────────────────────────────
# 跳板机主机名、内部工单系统域名、内部文档站、内部制品库地址等。
